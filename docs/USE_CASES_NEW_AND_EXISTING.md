# 📘 คู่มือการประยุกต์ใช้งานระบบ `RELAY`: โครงการใหม่ (Greenfield) และโครงการเดิม (Brownfield)

เอกสารฉบับนี้อธิบายขั้นตอนการนำระบบ **`RELAY`** ไปใช้งานจริงใน 2 สถานการณ์หลักของงานพัฒนาซอฟต์แวร์ ได้แก่ **การเริ่มต้นโครงการใหม่ตั้งแต่ศูนย์** และ **การนำระบบไปติดตั้งในโครงการเดิมที่มีโค้ดอยู่แล้ว** พร้อมวิธีการเชื่อมต่อกับโปรแกรม **Obsidian**

*(หมายเหตุ: ขั้นตอนด้านล่างสมมติว่าคุณได้ติดตั้งการตั้งค่าส่วนกลางด้วยคำสั่ง `./setup-mac.sh` หรือ `.\setup-win.ps1` เรียบร้อยแล้ว)*

---

## กรณีศึกษาที่ 1: การเริ่มต้นโครงการใหม่ตั้งแต่ศูนย์ (Greenfield Project)
*เหมาะสำหรับ: การสร้างแอปพลิเคชันหรือระบบใหม่ที่ต้องการวางโครงสร้าง `RELAY` ให้เรียบร้อยก่อนเริ่มเขียนโค้ด (Vibe Coding)*

### ขั้นตอนที่ 1.1: สร้างโฟลเดอร์โครงการ เริ่มต้น Git และสร้างโครงสร้าง `.relay/`

#### 🍎 บนระบบปฏิบัติการ macOS / Linux (Terminal):
```bash
# 1. สร้างโฟลเดอร์โครงการใหม่และเริ่มต้นระบบ Git
mkdir my-new-project && cd my-new-project
git init -b main

# 2. สร้างโครงสร้าง .relay/ ด้วยสคริปต์อัตโนมัติ (หรือใช้คำสั่ง mkdir -p .relay/tasks .relay/archive)
~/.agents/bin/relay-init . new
```

#### 🪟 บนระบบปฏิบัติการ Windows (PowerShell):
```powershell
# 1. สร้างโฟลเดอร์โครงการใหม่และเริ่มต้นระบบ Git
mkdir my-new-project; cd my-new-project
git init -b main

# 2. สร้างโครงสร้าง .relay/ ด้วยสคริปต์อัตโนมัติ (หรือใช้คำสั่ง mkdir -Force .relay\tasks, .relay\archive)
& "$HOME\.agents\bin\relay-init.ps1" . new
```

### ขั้นตอนที่ 1.2: เชื่อมต่อโฟลเดอร์ `.relay/` เข้ากับโปรแกรม Obsidian
1. เปิดโปรแกรม **Obsidian**
2. คลิกปุ่ม **"Open folder as vault"** (เปิดโฟลเดอร์เป็นคลังข้อมูล)
3. เลือกไปที่โฟลเดอร์ **`my-new-project/.relay`** แล้วกด **Open**
   *(การเลือกโฟลเดอร์ `.relay` เป็น Vault โดยตรง จะทำให้คุณเห็นไฟล์ `PROJECT_STATE.md`, โฟลเดอร์ `tasks/` และ `archive/` บนแถบด้านซ้ายของ Obsidian ได้ทันทีโดยไม่ต้องตั้งค่าเปิดไฟล์ซ่อน)*

### ขั้นตอนที่ 1.3: ดำเนินงานตามลำดับขั้นตอนที่ 1 ถึง 4 (Phase 1–4)
1. **ขั้นตอนที่ 1 (`@po` — การกำหนดความต้องการ):**
   เปิดใช้งาน CLI (`gemini` หรือ `claude`) ในโฟลเดอร์โครงการ แล้วสั่งงาน:
   ```text
   @po ฉันต้องการสร้างระบบ [ระบุชื่อและรายละเอียดของระบบที่ต้องการสร้าง] ช่วยซักถามความต้องการและขอบเขตของระบบทีละประเด็นจนชัดเจน แล้วสรุปเป็นเอกสารกำหนดความต้องการลงในไฟล์ .relay/tasks/20261028-initial-system/SPEC.md
   ```
   *(ตอบคำถามของ AI จนได้ไฟล์ `SPEC.md` ที่ครบถ้วน จากนั้นพิมพ์ `/clear` เพื่อล้างหน่วยความจำการสนทนา)*

2. **ขั้นตอนที่ 2 (`@arch` & `@pm` — การออกแบบสถาปัตยกรรมและวางแผนงาน):**
   ```text
   @arch @pm อ่านไฟล์ .relay/tasks/20261028-initial-system/SPEC.md แล้วออกแบบโครงสร้างระบบและเทคโนโลยีที่ใช้ลงในไฟล์ ARCH.md พร้อมแตกแผนการดำเนินงานเป็นข้อๆ ลงใน PLAN.md และบันทึกโครงสร้างตั้งต้นลงใน .relay/PROJECT_STATE.md
   ```
   *(เมื่อตรวจสอบแผนใน Obsidian เรียบร้อยแล้ว ให้พิมพ์ `/clear`)*

3. **ขั้นตอนที่ 3 (`@dev` — การพัฒนาโค้ดในสภาพแวดล้อมแยกอิสระ `Git Worktree`):**
   เปิดใช้งานกิ่งแยกด้วยคำสั่งมาตรฐาน (เช่น `claude --worktree initial-system` หรือ `git worktree add ../initial-system -b feat/initial-system`) แล้วสั่งงาน:
   ```text
   @dev อ่านเอกสารใน .relay/tasks/20261028-initial-system/ (SPEC.md, ARCH.md, PLAN.md) แล้วดำเนินการพัฒนาโค้ดและเขียนชุดทดสอบ (Unit Tests) ตามแผนที่กำหนด
   ```

4. **ขั้นตอนที่ 4 (`@qa` & `@sec` — การตรวจสอบคุณภาพและความปลอดภัย):**
   ```text
   @qa @sec ตรวจสอบผลงานตามเกณฑ์ใน .relay/tasks/20261028-initial-system/SPEC.md โดยรันชุดทดสอบจริง ตรวจสอบความปลอดภัยของ git diff และใช้ Playwright MCP ทดสอบหน้าเว็บพร้อมบันทึกภาพหน้าจอลงใน screenshots/ แล้วสรุปผลลงใน QA_REPORT.md
   ```
   เมื่อผ่านครบทุกข้อ ให้ทำการรวมโค้ด (Merge) เข้าสู่กิ่ง `main` และย้ายโฟลเดอร์ใบงานเข้าสู่ `.relay/archive/`

## กรณีศึกษาที่ 2: การนำ `RELAY` ไปใช้กับโครงการเดิมที่มีอยู่แล้ว (Brownfield / Existing Project)
*เหมาะสำหรับ: โครงการที่มีโค้ดเดิมอยู่แล้ว (เช่น พัฒนามาแล้วหลายเดือน หรือมีอยู่แล้ว 10+ โครงการ) และต้องการนำระบบ `RELAY` เข้าไปช่วยจัดระเบียบในการพัฒนาต่อหรือแก้ไขข้อผิดพลาด*

> [!IMPORTANT]
> **หัวใจสำคัญของโครงการเดิม:** ก่อนเริ่มสั่งแก้โค้ดในโครงการเก่า เราต้องสั่งให้ **`@arch`** ทำการสำรวจโครงสร้างโค้ดเดิม (Reverse-Engineering) เพื่อสรุปเป็นไฟล์ **`.relay/PROJECT_STATE.md`** เพียงครั้งเดียวก่อน เพื่อให้ในการทำงานทุกครั้งถัดไป AI เข้าใจสถาปัตยกรรมของโครงการเดิมได้ทันทีโดยไม่ต้องสแกนโค้ดใหม่ทั้งหมด

### ขั้นตอนที่ 2.1: สร้างโครงสร้าง `.relay/` ในโฟลเดอร์โครงการเดิม

#### 🍎 บนระบบปฏิบัติการ macOS / Linux (Terminal):
```bash
# 1. เข้าไปยังโฟลเดอร์โครงการเดิมของคุณ
cd /path/to/your-existing-project

# 2. รันสคริปต์สร้างโครงสร้าง .relay/ ในโหมดโครงการเดิม (existing)
~/.agents/bin/relay-init . existing
```

#### 🪟 บนระบบปฏิบัติการ Windows (PowerShell):
```powershell
# 1. เข้าไปยังโฟลเดอร์โครงการเดิมของคุณ
cd C:\path\to\your-existing-project

# 2. รันสคริปต์สร้างโครงสร้าง .relay/ ในโหมดโครงการเดิม (existing)
& "$HOME\.agents\bin\relay-init.ps1" . existing
```

### ขั้นตอนที่ 2.2: สั่งให้ `@arch` สแกนโครงการเดิมเพื่อสร้างไฟล์ `.relay/PROJECT_STATE.md` (ทำเพียงครั้งเดียว)
เปิดใช้งาน CLI (`claude` หรือ `gemini`) ในโฟลเดอร์โครงการเดิม แล้วคัดลอกคำสั่งมาตรฐานด้านล่างไปรัน:

```text
@arch ช่วยสำรวจและวิเคราะห์โครงสร้างของโครงการเดิมนี้ทั้งหมด (ประกอบด้วย Tech Stack, โครงสร้างโฟลเดอร์สำคัญ, รูปแบบฐานข้อมูล/Schema, รายการ API หลัก และคำสั่งที่ใช้ในการ Build/Test) แล้วสรุปเขียนทับลงในไฟล์ .relay/PROJECT_STATE.md ให้มีความชัดเจนและกระชับ (ความยาวไม่เกิน 2 หน้า) โดยห้ามแก้ไขไฟล์โค้ดใดๆ ของระบบ
```

เมื่อ AI สร้างไฟล์ `.relay/PROJECT_STATE.md` เสร็จแล้ว ให้เปิดตรวจสอบในโปรแกรม **Obsidian** (โดยคลิก `Open folder as vault` ➔ เลือกโฟลเดอร์ `.relay` ของโครงการนั้น) จากนั้นพิมพ์ `/clear` เพื่อล้างประวัติการสนทนา

### ขั้นตอนที่ 2.3: เริ่มต้นพัฒนาฟีเจอร์ใหม่หรือแก้ไขข้อผิดพลาดในโครงการเดิม
เมื่อมีไฟล์ `.relay/PROJECT_STATE.md` แล้ว โครงการเดิมของคุณจะพร้อมใช้งานระบบ `RELAY` เต็มรูปแบบทันที:
1. **ขั้นตอนที่ 1 (`@po`):** สั่งซักถามความต้องการของฟีเจอร์ที่ต้องการเพิ่มหรือปัญหาที่ต้องการแก้ไข เพื่อสร้างไฟล์ `.relay/tasks/YYYYMMDD-feature-name/SPEC.md`
2. **ขั้นตอนที่ 2 (`@arch` & `@pm`):** สั่งให้อ่าน `.relay/PROJECT_STATE.md` คู่กับ `SPEC.md` เพื่อระบุไฟล์เดิมที่ต้องแก้ไขลงใน `ARCH.md` และ `PLAN.md`
3. **ขั้นตอนที่ 3 (`@dev`):** เปิดกิ่งแยกด้วย `Git Worktree` (`claude --worktree fix-feature`) เพื่อแก้ไขโค้ดโดยไม่กระทบโค้ดหลักในกิ่ง `main`
4. **ขั้นตอนที่ 4 (`@qa` & `@sec`):** รันชุดทดสอบเดิมและชุดทดสอบใหม่ สแกนความปลอดภัยด้วย `differential-review` ทดสอบหน้าเว็บด้วย `Playwright MCP` บันทึก `QA_REPORT.md` และอัปเดต `.relay/PROJECT_STATE.md` ให้เป็นปัจจุบันเสมอ
