# 📘 คู่มือการประยุกต์ใช้งานระบบ `RELAY`: โครงการใหม่ (Greenfield) และโครงการเดิม (Brownfield)

เอกสารฉบับนี้อธิบายขั้นตอนการนำระบบ **`RELAY`** ไปใช้งานจริงผ่านหน้าจอควบคุมกลางแบบนำทาง 3 ขั้นตอนอัตโนมัติ (คำสั่ง **`relay`**) ใน 2 สถานการณ์หลักของงานพัฒนาซอฟต์แวร์ ได้แก่ **การเริ่มต้นโครงการใหม่ตั้งแต่ศูนย์** และ **การนำระบบไปติดตั้งในโครงการเดิมที่มีโค้ดอยู่แล้ว** พร้อมวิธีการเชื่อมต่อกับโปรแกรม **Obsidian**

---

## ขั้นที่ 1/3: การตั้งค่าค่าย AI, เลือก Model และตรวจสอบการ Login ให้ครบ 4 ตำแหน่ง

เมื่อคุณพิมพ์คำสั่ง `relay` ครั้งแรก (หรือพิมพ์ `relay config` / กด `c`) ระบบจะตรวจสอบความพร้อมจริง 3 ชั้น (ติดตั้ง CLI + Login บัญชีแล้ว + เลือก Model แล้ว) โดยคุณสามารถเลือก **Quick Setup ในคลิกเดียว** หรือกำหนดแยกทีละตำแหน่งได้ดังนี้:

- **ชุดแนะนำ Google AI Ultra (`agy`) + Codex (`codex`):**
  1. **ขั้นตอนที่ 1 (`@po` — การวิเคราะห์ความต้องการ):** `agy` (`gemini-4-argon-high`)
  2. **ขั้นตอนที่ 2 (`@arch & @pm` — การออกแบบและวางแผน):** `agy` (`claude-opus-5-5-high`)
  3. **ขั้นตอนที่ 3 (`@dev` — การพัฒนาโค้ดใน Git Worktree):** `agy` (`claude-sonnet-5-5-high`)
  4. **ขั้นตอนที่ 4 (`@qa & @sec` — การตรวจสอบคุณภาพและความปลอดภัย):** `codex` (`gpt-6.1-terra`)
- **ชุด All-Google AI Ultra (`ใช้ agy ทุกตำแหน่ง`):** ใช้โควต้า Google AI Ultra ครบทั้ง 4 ตำแหน่ง (`@po=gemini-4-argon-high`, `@arch=claude-opus-5-5-high`, `@dev=claude-sonnet-5-5-high`, `@qa=gpt-oss-120b-medium`)
- **ชุด Multi-Vendor (`agy` + `claude` + `codex`):** ผสมค่ายอิสระตามแพ็กเกจที่คุณมี
- **การตรวจสอบโควต้าคงเหลือ (`[u]` / `/quota` หรือ `relay quota`):**
  - หน้าจอ `relay` แสดงเปอร์เซ็นต์โควต้าคงเหลือทั้งแบบ **5 ชั่วโมง (`5h`)** และ **รายสัปดาห์ (`7d`)** ของทั้ง `agy (Gemini Models)`, `agy (Claude & GPT)`, `codex`, และ `claude` ให้เห็นทันทีในตารางตำแหน่งและแถบสรุปโควต้า
  - คุณสามารถกดปุ่ม **`u`** (หรือพิมพ์ `/quota` / รัน `relay quota`) เพื่อดึงข้อมูลโควต้าล่าสุดพร้อมหลอดโควต้า (`[███████░░░]`) และสลับค่ายได้ทันทีหากค่ายใดใกล้หมดโควต้า

*(เมื่อทั้ง 4 ตำแหน่งขึ้นสถานะ `● พร้อมใช้` ครบ `4/4` แล้ว หน้าจอ `relay` จะข้ามเข้าสู่ **ขั้นที่ 2/3** ให้อัตโนมัติ)*

## กรณีศึกษาที่ 1: การเริ่มต้นโครงการใหม่ตั้งแต่ศูนย์ (Greenfield Project)
*เหมาะสำหรับ: การสร้างแอปพลิเคชันหรือระบบใหม่ที่ต้องการวางโครงสร้าง `RELAY` ให้เรียบร้อยก่อนเริ่มเขียนโค้ด*

### ขั้นตอนที่ 1.1: เปิดคำสั่ง `relay` และเตรียมโครงสร้าง `.relay/` (ขั้นที่ 2/3)
> 💡 **ทำงานแบบแยกโปรเจกต์อิสระ (`On-Demand & Per-Project`):** กระบวนการทีม 4 ขั้นตอนของ `RELAY` จะทำงานเฉพาะในโปรเจกต์ที่มีโฟลเดอร์ `.relay/` เท่านั้น โปรเจกต์อื่นในเครื่องที่ยังไม่ได้ติดตั้ง `.relay/` จะไม่ถูกบังคับใช้กฎ `SPEC.md` หรือ `Git Worktree` และข้อมูลของแต่ละโปรเจกต์จะถูกเก็บแยกใน `.relay/` ของโฟลเดอร์นั้นๆ ไม่ปะปนกัน

1. คุณสามารถพิมพ์คำสั่ง `relay` จากที่ใดก็ได้:
   - **กรณีพิมพ์ `relay` ในโฟลเดอร์ Home (`~`) หรือกด `[f]` สลับโปรเจกต์:** ระบบจะแสดงรายการโปรเจกต์ที่จำแนกสถานะอย่างชัดเจน โดยนำโปรเจกต์ที่ติดตั้ง RELAY แล้ว (**`● [RELAY]`** สีเขียว พร้อมแสดง `Task: <id>` หรือ `พร้อมเริ่มงานใหม่`) ขึ้นมาไว้ด้านบนสุดเสมอ ตามด้วยโฟลเดอร์โปรเจกต์ทั่วไป (**`○ [ทั่วไป]`** สีเทา) และตัวเลือก `[n]` สำหรับสร้างโปรเจกต์ใหม่พร้อม `git init` และ `.relay/` ในคลิกเดียว
   - **กรณีสร้างโฟลเดอร์เองแล้วพิมพ์ `relay`:**
     ```bash
     mkdir my-new-project && cd my-new-project
     git init -b main
     relay
     ```
     ระบบจะแสดงหน้าจอ **ขั้นที่ 2/3 (`เตรียมโครงสร้าง .relay/`)** ให้คุณกด Enter ที่ข้อ **`[1] ★ เริ่มโปรเจกต์ใหม่ตั้งแต่ศูนย์ในโฟลเดอร์นี้ (Greenfield)`**
2. *(ทางเลือกเสริม — ไม่บังคับ)* หากต้องการหน้าจอดูเอกสารแยกต่างหาก สามารถเปิดโปรแกรม **Obsidian** ➔ คลิก **"Open folder as vault"** ➔ เลือกโฟลเดอร์ **`my-new-project/.relay`** (หรือเปิดอ่านไฟล์ `.md` ใน VS Code / Editor ปกติได้ทันที)

### ขั้นตอนที่ 1.2: ดำเนินงานตามลำดับขั้นตอนที่ 1 ถึง 5 ในหน้าจอ `relay` (ขั้นที่ 3/3)
เมื่อมี `.relay/PROJECT_STATE.md` แล้ว หน้าจอ `relay` จะเข้าสู่ **ขั้นที่ 3/3** และเลื่อนแถบสีน้ำเงิน `❯` ไปยังขั้นตอนที่มีเครื่องหมาย `★` ให้อัตโนมัติ:
1. **กด Enter ที่ข้อ `[1]` (ขั้นตอนที่ 1 — `@po`):**
   - ระบบจะถามชื่อใบงานย่อ (เช่น `initial-system`) และความต้องการเบื้องต้น จากนั้นจะเปิด CLI และ Model ที่ผูกไว้กับ `@po` (เช่น `agy --model gemini-4-argon-high`) ขึ้นมาซักถามความต้องการและสร้างไฟล์ `.relay/tasks/YYYYMMDD-initial-system/SPEC.md`
2. **กด Enter ที่ข้อ `[2]` (ขั้นตอนที่ 2 — `@arch & @pm`):**
   - เมื่อมี `SPEC.md` แล้ว ตัวชี้ `❯` จะเลื่อนมาที่ข้อ `[2]` อัตโนมัติ กด Enter เพื่อให้อ่าน `PROJECT_STATE.md` + `SPEC.md` แล้วสร้างไฟล์ `ARCH.md` และ `PLAN.md`
3. **กด Enter ที่ข้อ `[3]` (ขั้นตอนที่ 3 — `@dev`):**
   - เมื่อมี `PLAN.md` แล้ว ตัวชี้ `❯` จะเลื่อนมาที่ข้อ `[3]` อัตโนมัติ กด Enter เพื่อสร้างสภาพแวดล้อมแยกอิสระ (`Git Worktree` ที่ `.relay/worktrees/<task-id>`) และเปิด CLI ของ `@dev` เพื่อพัฒนาโค้ดและชุดทดสอบในกิ่งแยกโดยไม่กระทบโค้ดหลัก
4. **กด Enter ที่ข้อ `[4]` (ขั้นตอนที่ 4 — `@qa & @sec`):**
   - เปิด CLI ของ `@qa` เพื่อรันชุดทดสอบจริง, ตรวจสอบความปลอดภัยของ `git diff`, ทดสอบหน้าเว็บด้วย `Playwright MCP` (เฉพาะกรณีมีงานแก้ Web UI) และสรุปผลลงใน `QA_REPORT.md` คู่กับ `QA_VERDICT.json`
   - **ทางลัดอัตโนมัติ (`[a]` / `/loop` — Bounded Auto-Relay Loop):** เมื่อมี `SPEC.md` จากข้อ `[1]` แล้ว คุณสามารถกดปุ่ม **`a`** เพื่อให้ระบบรันขั้นตอนที่ `2 (@arch) ➔ 3 (@dev) ⇄ 4 (@qa)` ต่อเนื่องให้อัตโนมัติพร้อมเบรกโควต้าขั้นต่ำ `20%` และจำกัดการวนแก้บั๊กไม่เกิน `3 รอบ`
   - **ทางลัดงานเล็ก/แก้บั๊ก (`[x]` / `/fast` — Fast Track):** สำหรับงานขนาดเล็กที่ไม่ต้องการพิธีกรรมเอกสาร 4 ขั้นตอน สามารถกดปุ่ม **`x`** เพื่อข้าม `@po` และ `@arch` แล้วส่ง `@dev` ลงมือทำใน Git Worktree ได้ทันที พร้อมกด **`v`** (`relay stats`) เพื่อดูจำนวน Token และเวลาที่ใช้จริงในแต่ละขั้นตอนและแต่ละโมเดล
5. **กด Enter ที่ข้อ `[5]` (ขั้นตอนที่ 5 — `Self-Learn + Merge & Archive`):**
   - เมื่อ `@qa` ตรวจรับผ่าน (`QA_VERDICT.json` เป็น `PASS`) ตัวชี้ `❯` จะเลื่อนมาที่ข้อ `[5]` อัตโนมัติ (ถ้ายังไม่ผ่าน ระบบจะแนะนำ `[3]` หรือ `[a]` ให้แก้ไขก่อน) กด Enter เพื่อตรวจ commit, ผสานโค้ดเข้าสู่กิ่ง `main`, บันทึกใบงานลง `PROJECT_STATE.md`, เสนอบทเรียนเข้าคิว `PENDING.md` และย้ายใบงานเข้าสู่ `.relay/archive/`
   - จากนั้นกด **`l`** เพื่อทบทวนและอนุมัติบทเรียน — เฉพาะข้อที่อนุมัติจะถูกส่งให้ AI ในใบงานถัดไป

## กรณีศึกษาที่ 2: การนำ `RELAY` ไปใช้กับโครงการเดิมที่มีอยู่แล้ว (Brownfield / Existing Project)
*เหมาะสำหรับ: โครงการที่มีโค้ดเดิมอยู่แล้ว และต้องการนำระบบ `RELAY` เข้าไปช่วยจัดระเบียบในการพัฒนาต่อหรือแก้ไขข้อผิดพลาด*

### ขั้นตอนที่ 2.1: เปิดหน้าจอ `relay` ในโฟลเดอร์โครงการเดิม (เลือกได้ 2 แนวทางตามขนาดงาน)
1. เปิด Terminal / PowerShell เข้าไปยังโฟลเดอร์โครงการเดิมของคุณแล้วพิมพ์คำสั่ง **`relay`**:
   ```bash
   cd /path/to/your-existing-project
   relay
   ```
2. หน้าจอ `relay` จะแสดง **ขั้นที่ 2/3 (`เตรียมโครงสร้าง .relay/`)** ซึ่งคุณเลือกได้ตามความเหมาะสมของงาน (ไม่จำเป็นต้องใช้โปรแกรม Obsidian):
   - **แนวทางที่ A — แก้ไขโค้ดหรือแก้บั๊กขนาดเล็กทันที (ไม่ต้องให้ AI สแกนทั้งโปรเจกต์ก่อน):**
     กด **`[1]`** เพื่อสร้างโครงสร้าง `.relay/` ตั้งต้นทันที (ไม่เรียก AI และไม่เสีย Token) ➔ เมื่อเข้าหน้าหลักแล้วกด **`[x]` (`Fast Track`)** เพื่อสั่ง `@dev` แก้ไขโค้ดใน Git Worktree ได้ทันที
   - **แนวทางที่ B — ให้ `@arch` สแกนทำความเข้าใจโปรเจกต์เดิมเก็บไว้ใน `.relay/PROJECT_STATE.md` 1 ครั้ง (สำหรับโปรเจกต์ที่จะพัฒนาต่อเนื่องหลายใบงาน):**
     เลือก **`[2] นำ RELAY มาใช้กับโปรเจกต์เดิมที่มีโค้ดอยู่แล้ว (Brownfield — ให้ @arch สแกนสร้าง PROJECT_STATE.md)`** ระบบจะเปิด CLI ของ `@arch` ขึ้นมาสแกนโครงสร้างโค้ดเดิม (Tech Stack, โครงสร้างโฟลเดอร์, Database Schema, API และคำสั่งรันเทสต์ เช่น `npm test` หรือ `flutter analyze && flutter test`) เพื่อสรุปเป็นไฟล์ **`.relay/PROJECT_STATE.md`** (ความยาวไม่เกิน 2 หน้า) เพียงครั้งเดียว โดยไม่แก้ไขโค้ดเดิม

### ขั้นตอนที่ 2.2: เริ่มต้นเพิ่มฟีเจอร์ใหม่หรือแก้ไขข้อผิดพลาดในโครงการเดิม (ขั้นที่ 3/3)
เมื่อโครงการเดิมมีไฟล์ `.relay/PROJECT_STATE.md` เรียบร้อยแล้ว หน้าจอ `relay` จะเข้าสู่ **ขั้นที่ 3/3** ทันที:
- กด **`1` (`@po`)** เพื่อกำหนดความต้องการของฟีเจอร์ใหม่หรือปัญหาที่ต้องการแก้ไขลงใน `SPEC.md`
- กด **`2` (`@arch & @pm`)** ซึ่งจะอ่าน `.relay/PROJECT_STATE.md` คู่กับ `SPEC.md` ทำให้ทราบตำแหน่งไฟล์เดิมที่ต้องแก้ไขทันทีโดยไม่ต้องสแกนโค้ดใหม่ทั้งหมด
- กด **`3` (`@dev`)** เพื่อแยกกิ่ง `Git Worktree` ออกไปแก้ไขโค้ดอย่างปลอดภัย
- กด **`4` (`@qa & @sec`)** เพื่อทดสอบและตรวจสอบความปลอดภัยก่อนกด **`5`** เพื่อรวมโค้ดกลับเข้าสู่กิ่ง `main`
