# 📘 คู่มือการประยุกต์ใช้งานระบบ `RELAY`: โครงการใหม่ (Greenfield) และโครงการเดิม (Brownfield)

เอกสารฉบับนี้อธิบายขั้นตอนการนำระบบ **`RELAY`** ไปใช้งานจริงผ่านหน้าจอควบคุมกลาง (คำสั่ง **`relay`**) ใน 2 สถานการณ์หลักของงานพัฒนาซอฟต์แวร์ ได้แก่ **การเริ่มต้นโครงการใหม่ตั้งแต่ศูนย์** และ **การนำระบบไปติดตั้งในโครงการเดิมที่มีโค้ดอยู่แล้ว** พร้อมวิธีการเชื่อมต่อกับโปรแกรม **Obsidian**

---

## การเตรียมความพร้อมก่อนเริ่มโครงการ: การตั้งค่าค่าย AI ประจำตำแหน่ง (`relay config`)

หลังจากติดตั้งระบบ `RELAY` ด้วยคำสั่ง `./setup-mac.sh` (หรือ `.\setup-win.ps1` บน Windows) คุณสามารถกำหนดไว้ล่วงหน้าได้ว่าต้องการให้แต่ละตำแหน่งใช้ AI ของค่ายใด (`claude`, `codex`, หรือ `gemini`) โดยเปิด Terminal แล้วพิมพ์:

```bash
relay config
```

ระบบจะให้คุณเลือกจับคู่ค่าย AI สำหรับทั้ง 4 ขั้นตอน:
1. **ขั้นตอนที่ 1 (`@po` — การวิเคราะห์ความต้องการ):** เช่น `gemini` หรือ `claude`
2. **ขั้นตอนที่ 2 (`@arch & @pm` — การออกแบบและวางแผน):** เช่น `claude` หรือ `gemini`
3. **ขั้นตอนที่ 3 (`@dev` — การพัฒนาโค้ดใน Git Worktree):** เช่น `claude`
4. **ขั้นตอนที่ 4 (`@qa & @sec` — การตรวจสอบคุณภาพและความปลอดภัย):** เช่น `codex` หรือ `claude`

*(คุณสามารถเลือกบันทึกไว้ที่ระดับส่วนกลาง `~/.agents/relay-roles.conf` เพื่อใช้กับทุกโครงการ หรือบันทึกไว้ที่ `.relay/roles.conf` เพื่อกำหนดแยกเฉพาะโครงการได้)*

## กรณีศึกษาที่ 1: การเริ่มต้นโครงการใหม่ตั้งแต่ศูนย์ (Greenfield Project)
*เหมาะสำหรับ: การสร้างแอปพลิเคชันหรือระบบใหม่ที่ต้องการวางโครงสร้าง `RELAY` ให้เรียบร้อยก่อนเริ่มเขียนโค้ด (Vibe Coding)*

### ขั้นตอนที่ 1.1: สร้างโฟลเดอร์โครงการและเปิดหน้าจอควบคุมกลาง `relay`

```bash
# 1. สร้างโฟลเดอร์โครงการใหม่และเริ่มต้นระบบ Git
mkdir my-new-project && cd my-new-project
git init -b main

# 2. เปิดหน้าจอควบคุมกลางของ RELAY (ใช้หน้าต่าง Terminal นี้เพียงหน้าต่างเดียวตลอดการทำงาน)
relay
```

### ขั้นตอนที่ 1.2: เตรียมโครงสร้าง `.relay/` และเชื่อมต่อโปรแกรม Obsidian
1. ในหน้าจอควบคุมกลางของ `relay` ให้พิมพ์ **`i`** แล้วเลือก **`[1] โครงการใหม่ตั้งแต่ศูนย์ (Greenfield Project)`** ระบบจะสร้างโฟลเดอร์ `.relay/tasks/`, `.relay/archive/` และไฟล์ `.relay/PROJECT_STATE.md` ตั้งต้นให้อัตโนมัติ
2. เปิดโปรแกรม **Obsidian** ➔ คลิก **"Open folder as vault"** ➔ เลือกโฟลเดอร์ **`my-new-project/.relay`** เพื่อใช้เปิดดูเอกสารควบคู่ไปกับหน้าต่าง Terminal

### ขั้นตอนที่ 1.3: ดำเนินงานตามลำดับขั้นตอนที่ 1 ถึง 5 ภายในหน้าจอ `relay` เดียว
ในหน้าจอควบคุมกลางของ `relay` คุณสามารถกดเลือกหมายเลขตามลำดับโดยไม่ต้องพิมพ์สลับโปรแกรมเอง:
1. **กด `1` (เริ่มขั้นตอนที่ 1 — `@po`):**
   - ระบบจะถามชื่อใบงานย่อ (เช่น `initial-system`) และความต้องการเบื้องต้น จากนั้นจะเปิด CLI ของค่ายที่คุณผูกไว้กับ `@po` ขึ้นมาในหน้าต่างเดิมทันที
   - สนทนาตอบคำถามของ `@po` จนได้ไฟล์ `.relay/tasks/YYYYMMDD-initial-system/SPEC.md` ที่ครบถ้วน แล้วพิมพ์ **`/exit`** เพื่อกลับสู่เมนูหลักของ `relay`
2. **กด `2` (เริ่มขั้นตอนที่ 2 — `@arch & @pm`):**
   - ระบบจะสลับไปเปิด CLI ของค่ายที่คุณผูกไว้กับ `@arch` พร้อมส่งคำสั่งให้อ่าน `SPEC.md` เพื่อสร้างไฟล์ `ARCH.md`, `PLAN.md` และอัปเดต `PROJECT_STATE.md` เมื่อเสร็จแล้วให้พิมพ์ **`/exit`**
3. **กด `3` (เริ่มขั้นตอนที่ 3 — `@dev`):**
   - ระบบจะสร้างสภาพแวดล้อมแยกอิสระ (`Git Worktree` ที่ `.relay/worktrees/<task-id>`) ให้อัตโนมัติ และเปิด CLI ของค่ายที่ผูกไว้กับ `@dev` เพื่อพัฒนาโค้ดและชุดทดสอบในกิ่งแยกโดยไม่กระทบโค้ดหลัก เมื่อเสร็จแล้วให้พิมพ์ **`/exit`**
4. **กด `4` (เริ่มขั้นตอนที่ 4 — `@qa & @sec`):**
   - ระบบจะเปิด CLI ของค่ายที่ผูกไว้กับ `@qa` เพื่อรันชุดทดสอบจริง (0 Token), ตรวจสอบความปลอดภัยของ `git diff`, ทดสอบหน้าเว็บด้วย `Playwright MCP` และสรุปผลลงใน `QA_REPORT.md` เมื่อเสร็จแล้วให้พิมพ์ **`/exit`**
5. **กด `5` (ผสานโค้ดและจัดเก็บใบงาน — `Merge & Archive`):**
   - ระบบจะแสดงรายการไฟล์ที่เปลี่ยนแปลง เมื่อคุณกดยืนยัน ระบบจะผสานโค้ดเข้าสู่กิ่ง `main` ลบ Worktree ชั่วคราว และย้ายใบงานเข้าสู่ `.relay/archive/` ให้อัตโนมัติ

## กรณีศึกษาที่ 2: การนำ `RELAY` ไปใช้กับโครงการเดิมที่มีอยู่แล้ว (Brownfield / Existing Project)
*เหมาะสำหรับ: โครงการที่มีโค้ดเดิมอยู่แล้ว (เช่น โครงการที่พัฒนามาก่อนหน้านี้โดยไม่เคยใช้ `RELAY`) และต้องการนำระบบ `RELAY` เข้าไปช่วยจัดระเบียบในการพัฒนาต่อหรือแก้ไขข้อผิดพลาด*

### ขั้นตอนที่ 2.1: เปิดหน้าจอ `relay` ในโฟลเดอร์โครงการเดิมและสั่งสแกนสร้าง `PROJECT_STATE.md`
1. เปิด Terminal / PowerShell เข้าไปยังโฟลเดอร์โครงการเดิมของคุณแล้วพิมพ์คำสั่ง **`relay`**:
   ```bash
   cd /path/to/your-existing-project
   relay
   ```
2. ในหน้าจอควบคุมกลางของ `relay` ให้พิมพ์ **`i`** แล้วเลือก **`[2] โครงการเดิมที่มีโค้ดอยู่แล้ว (Brownfield / Existing Project)`**:
   - ระบบจะสร้างโครงสร้างโฟลเดอร์ `.relay/` และเปิด CLI ของค่ายที่ผูกไว้กับ `@arch` ขึ้นมาทันที พร้อมป้อนคำสั่งให้สแกนโครงสร้างโค้ดเดิม (Tech Stack, โครงสร้างโฟลเดอร์, Database Schema, API และคำสั่งรันเทสต์) เพื่อสรุปเป็นไฟล์ **`.relay/PROJECT_STATE.md`** (ความยาวไม่เกิน 2 หน้า) โดยไม่แก้ไขโค้ดเดิม
   - เมื่อ AI สร้างไฟล์ `.relay/PROJECT_STATE.md` เสร็จสิ้น ให้พิมพ์ **`/exit`** เพื่อกลับสู่หน้าจอควบคุมกลางของ `relay`

### ขั้นตอนที่ 2.2: เริ่มต้นเพิ่มฟีเจอร์ใหม่หรือแก้ไขข้อผิดพลาดในโครงการเดิม
เมื่อโครงการเดิมมีไฟล์ `.relay/PROJECT_STATE.md` เรียบร้อยแล้ว คุณสามารถสั่งงานผ่านหน้าจอ `relay` ได้เหมือนโครงการใหม่ทุกประการ:
- กด **`1` (`@po`)** เพื่อกำหนดความต้องการของฟีเจอร์ใหม่หรือปัญหาที่ต้องการแก้ไขลงใน `SPEC.md`
- กด **`2` (`@arch & @pm`)** ซึ่งจะอ่าน `.relay/PROJECT_STATE.md` คู่กับ `SPEC.md` ทำให้ทราบตำแหน่งไฟล์เดิมที่ต้องแก้ไขทันทีโดยไม่ต้องสแกนโค้ดใหม่ทั้งหมด
- กด **`3` (`@dev`)** เพื่อแยกกิ่ง `Git Worktree` ออกไปแก้ไขโค้ดอย่างปลอดภัย
- กด **`4` (`@qa & @sec`)** เพื่อทดสอบและตรวจสอบความปลอดภัยก่อนกด **`5`** เพื่อรวมโค้ดกลับเข้าสู่กิ่ง `main`
