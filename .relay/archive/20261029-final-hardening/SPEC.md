# SPEC — ปรับปรุงรอบสุดท้ายก่อนเผยแพร่ (20261029-final-hardening)

> ขอบเขตที่ผู้ใช้ยืนยัน: F1, F2, F3, F4, F7 + F5 (เพิ่มเพื่อความสมบูรณ์) จากรีวิวมุมมองวิศวกร AI
> นอกขอบเขต: Windows parity, sandbox ของ agy (F6 — ยังทดสอบกับ CLI จริงไม่ได้), แยกไฟล์ `relay.sh` (F8), ชุด eval ผลงาน agent (F9), Self-Learning ด้วย AI (M2), ตัดข้อความจอแคบ (M5)

## F1 — คำอ้างในเอกสารต้องตรงความจริง
- เอาคำอ้าง "ลด Token 85–90%" และ "ปลอดภัยตามเงื่อนไขแพ็กเกจรายเดือน 100%" ออก แทนด้วยข้อความที่ตรวจสอบได้
- แก้ `ARCHITECTURE_DEEP_DIVE.md` ข้อ 3 ไม่ให้ขัดกับการมี Auto-Loop: อธิบายความเสี่ยงและวิธีที่ RELAY ลดความเสี่ยง (ใช้ CLI ทางการในโหมด non-interactive ที่แต่ละค่ายเปิดให้, จำกัดรอบ/เวลา/โควต้า, คนคุมหัวท้าย) และแนะนำให้ผู้ใช้ตรวจเงื่อนไขแพ็กเกจตนเอง
- เพิ่มหัวข้อ "ข้อจำกัดที่ควรทราบก่อนใช้งาน" ใน README

## F2 — บทเรียนสะสมต้องผ่านการอนุมัติของคนก่อนเข้า prompt
- การสกัดบทเรียน (ขั้นตอนที่ 5 และ `relay learn --auto`) เขียนกฎที่เสนอลง `.relay/skills/project-learned/PENDING.md` เท่านั้น — ไม่แตะ `SKILL.md`
- เมนู `[l]` แสดงจำนวนที่รออนุมัติ ให้เลือกอนุมัติรายข้อ (`1,3`), ทั้งหมด (`a`), หรือปฏิเสธทั้งหมด (`x`); ข้อที่อนุมัติย้ายเข้า `SKILL.md` (ไม่ซ้ำ, ไม่เกิน 25 ข้อ), ทุกการตัดสินใจบันทึกใน `LEDGER.md`
- Prompt ของ agent แนบเฉพาะ `SKILL.md` (กฎที่อนุมัติแล้ว)
- แดชบอร์ดแสดง `N กฎ • M รออนุมัติ`

## F3 — ผลตรวจรับแบบมีโครงสร้าง
- `@qa` ต้องเขียน `.relay/tasks/<task>/QA_VERDICT.json`: `{"verdict":"PASS|FAIL","failed_criteria":[],"tests_run":[],"summary":""}`
- ตัดสินจาก JSON ก่อน: `PASS` ต้องไม่มี `failed_criteria`; JSON เสียรูปแบบ ➔ ไม่นับว่าผ่าน; ไม่มี JSON ➔ ใช้ `VERDICT:` ใน `QA_REPORT.md` เป็นทางสำรองและบันทึกว่าใช้ทางสำรอง
- ก่อน `@qa` แต่ละรอบ ย้ายไฟล์ JSON เก่าออกพร้อมรายงานเก่า
- แดชบอร์ด: ถ้าผลล่าสุดไม่ผ่าน ให้แนะนำ `[3]`/`[a]` แทน `[5]`; ขั้นตอนที่ 5 เตือนและขอยืนยันเพิ่มเมื่อยังไม่ผ่าน QA

## F4 — `PROJECT_STATE.md` อัปเดตหลังผสานสำเร็จเท่านั้น
- เอาคำสั่งแก้ `PROJECT_STATE.md` ออกจาก prompt ของ `@qa` และห้ามแก้ไฟล์นี้ใน Worktree
- เลิกคัดลอก `PROJECT_STATE.md` จาก Worktree กลับกิ่งหลัก
- หลังผสานสำเร็จ บันทึกใบงานลงหัวข้อ "ประวัติใบงานที่ผสานแล้ว" ใน `PROJECT_STATE.md` (วันที่, รหัสใบงาน, หัวข้อ SPEC, commit) เก็บล่าสุด 15 รายการ

## F5 — บันทึกการทำงานต่อขั้น
- ทุกครั้งที่เรียก agent (ทั้งแบบโต้ตอบและ Auto-Loop) เพิ่ม 1 บรรทัดใน `.relay/tasks/<task>/RUN_LOG.jsonl`: เวลาเริ่ม/จบ, ระยะเวลา, ขั้น, ค่าย, โมเดล, exit code, โควต้า 5h/7d ก่อน–หลัง
- จบ Auto-Loop แสดงสรุปเวลาและโควต้าที่ใช้ต่อขั้น

## F7 — ไม่แสดงโควต้าเก่าแบบเงียบ
- บันทึกสถานะการดึงข้อมูลต่อค่าย (สำเร็จ/ไม่สำเร็จ/ยังไม่ Login) และเวลาที่ดึงสำเร็จล่าสุด
- ถ้าดึงไม่สำเร็จ ตารางแสดง `? NN%` สีจาง พร้อม `ดึงไม่ได้ • ค่าเมื่อ HH:MM`; หน้า `[u]` แสดงคำเตือน; Quota Guard แจ้งว่าใช้ค่าล่าสุด

## เกณฑ์ตรวจรับ
- **AC-1** ไม่มีคำอ้าง 85–90% / 100% ToS ในเอกสาร และ ARCHITECTURE ข้อ 3 ไม่ขัดกับ Auto-Loop
- **AC-2** ขั้นตอนที่ 5 สร้าง `PENDING.md` แต่ไม่แก้ `SKILL.md`; อนุมัติ `1` ข้อแล้วเข้า `SKILL.md` เฉพาะข้อนั้น; LEDGER บันทึกทั้งอนุมัติและปฏิเสธ
- **AC-3** JSON PASS ➔ ผ่าน; JSON PASS แต่มี failed_criteria ➔ ไม่ผ่าน; JSON เสีย ➔ ไม่ผ่าน; ไม่มี JSON แต่ MD มี PASS ➔ ผ่านพร้อมบันทึกว่าใช้ทางสำรอง
- **AC-4** Loop และขั้นตอนที่ 4 ไม่เปลี่ยน `PROJECT_STATE.md` ของกิ่งหลัก; หลังผสานมีรายการใบงานในหัวข้อประวัติ
- **AC-5** `RUN_LOG.jsonl` มีหนึ่งบรรทัดต่อการเรียก agent และเป็น JSON ที่อ่านได้
- **AC-6** ค่ายที่ดึงโควต้าไม่สำเร็จแสดง `?` และ `ดึงไม่ได้`
- **AC-7** ชุดเทสต์เดิม (31 ข้อ) ยังผ่านทั้งหมด + `bash -n` ผ่าน
