- **ปัญหา 1 (จากการทดสอบจริง):** ทุกงานมี "กฎ" ที่คัดบรรทัดจาก SPEC/ARCH/QA ด้วยคำสำคัญ (ต้อง, ห้าม, worktree ฯลฯ) ➔ เป็นข้อความเฉพาะงาน ผู้ใช้ต้องกดปฏิเสธทุกครั้ง
- **ปัญหา 2 (จากการทดสอบจริง):** ผสานแล้ว `npm run dev` ใช้ไม่ได้ เพราะ @dev ติดตั้ง dependency ใน Worktree ที่ถูกลบไปแล้ว และ RELAY ไม่ได้บอก
- **ข้อจำกัด:** ไม่เรียก AI • ไม่รันคำสั่งติดตั้งให้เอง (ใช้เน็ตและเวลา) แค่บอกคำสั่ง

## เกณฑ์ตรวจรับ (Acceptance Criteria)
- [ ] Self-Learning เสนอเฉพาะบทเรียนจากหลักฐาน: มี `QA_VERDICT.before-round-*.json` ที่ FAIL และผลสุดท้าย PASS • เลิกคัดบรรทัดจาก SPEC/ARCH/QA ด้วยคำสำคัญ
- [ ] ไม่มีบทเรียนใหม่ ➔ แจ้งหนึ่งบรรทัดตามจริง ไม่เขียน LEDGER ว่าง และไม่สร้าง PENDING.md ว่าง
- [ ] หลังผสานสำเร็จ ถ้า merge เปลี่ยนไฟล์ dependency (เช่น package.json / lockfile, pubspec.yaml, requirements.txt, go.mod) ➔ แสดงคำสั่งติดตั้งที่ตรงกับไฟล์ แยกตามโฟลเดอร์ (เช่น `npm ci` เมื่อมี package-lock.json)
- [ ] ไม่มีไฟล์ dependency เปลี่ยน ➔ ไม่แสดงอะไรเพิ่ม
- [ ] ชุดทดสอบเดิมที่อาศัยการคัดคำสำคัญปรับมาใช้หลักฐาน FAIL ➔ PASS และชุดทดสอบทั้งหมดผ่าน
